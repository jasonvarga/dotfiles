# Create Pull Request

Create a pull request in the current repo from the current branch using `gh`.

## Instructions

1. **Check for uncommitted changes**:
   ```bash
   git status --porcelain
   ```
   If there are any uncommitted changes, **stop and inform the user**. Ask whether they should be committed before continuing. Do not commit without their go-ahead (per global instructions, never commit without asking).

2. **Gather branch and repo context** (in parallel):
   ```bash
   git rev-parse --abbrev-ref HEAD
   gh repo view --json nameWithOwner,defaultBranchRef -q '{repo: .nameWithOwner, default: .defaultBranchRef.name}'
   ```
   - If the current branch is the default branch, stop and tell the user — they likely don't want to PR the default branch into itself.

3. **Determine the title convention** by inspecting recent PRs:
   ```bash
   gh pr list --state all --limit 20 --json title,baseRefName
   ```
   - Look for a consistent prefix pattern, e.g. a version-line tag like `[6.x]` or `[5.x]`.
   - If such a prefix is used, match it. Pick the prefix based on the **base branch** the PR will target (e.g. PRs targeting `6.x` use `[6.x]`).
   - If no convention is apparent, use a plain descriptive title.

4. **Review the commits and diff** to write the title and body:
   ```bash
   git log <base>..HEAD --oneline
   ```
   - Title: concise, conforming to the convention from step 3.
   - Body: summarize what changed and why. Match the tone/structure of recent PRs if there's an obvious template.
   - Do **not** add a "generated by Claude" / "Co-authored-by Claude" line or any similar attribution.

5. **Confirm with the user** before creating: show the target base branch, title, and body. Wait for approval.

6. **Create the PR**:
   ```bash
   gh pr create --base <base> --title "<title>" --body "<body>"
   ```
   `gh pr create` pushes the current branch automatically if it has no upstream — no separate `git push` needed.

7. Report the resulting PR URL.
